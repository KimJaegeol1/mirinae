# 서버 끄고 다시 켜기 — 명령어와 그 뜻

"서버"는 사실 터미널 탭 두 개예요.

| 탭 | 프로세스 | 역할 | 언제 필요 |
|---|---|---|---|
| ① | `npm run mock` (wrangler) | 미리내 백엔드 본체. `localhost:8787` | 항상 |
| ② | `cloudflared tunnel …` | ①을 인터넷 https 주소로 노출 | **아이폰 Scriptable을 붙일 때만** (Android 에뮬레이터·시뮬레이터는 불필요) |

## 끄기

각 탭에서 **Ctrl+C**. 그게 전부예요. 서버 데이터(연결·세션)는 `backend/.wrangler/state/`에 파일로 남아 있어서 껐다 켜도 유지됩니다. 단, 가짜 은행의 계좌·잔액은 메모리에만 있어서 ①을 끄면 사라져요(앱 쪽 연결은 남아 있으니 다시 켜면 첫 조회 때 다시 등록됨 — 잔액은 초기값으로 돌아감).

> 순서 팁: ②(터널)는 살려두고 ①만 껐다 켜면 아이폰 설정을 안 건드려도 됩니다. 터널 주소는 ②가 살아 있는 동안만 유지되거든요.

## 다시 켜기 — 백엔드 (탭 ①)

```
cd ~/dev/mirinae-local-mvp-v0.7.0/backend
npm run mock
```

- `cd …/backend` — 백엔드 폴더로 이동. `package.json`이 있는 곳에서만 `npm run`이 동작해요.
- `npm run mock` — `package.json`의 `scripts.mock`에 적힌 명령을 실행. 풀어 쓰면 `wrangler dev -c wrangler.mock.jsonc --port 8787 --test-scheduled`:
  - `wrangler dev` — Cloudflare의 개발 도구. 배포하지 않고 Worker 코드를 내 컴퓨터에서 돌림
  - `-c wrangler.mock.jsonc` — 운영 설정(`wrangler.jsonc`) 대신 mock 설정 사용. 여기에 가짜 은행 바꿔치기(alias)·초대코드·더미 키가 있음
  - `--port 8787` — 주소가 `http://localhost:8787`이 되도록. Android 에뮬레이터 debug 빌드가 이 포트를 보고 있음
  - `--test-scheduled` — 20분마다 도는 동기화(cron)를 `curl "http://localhost:8787/__scheduled?cron=*/20+*+*+*+*"`로 수동 실행할 수 있게 함

`[wrangler:info] Ready on http://localhost:8787`이 뜨면 켜진 거예요. 확인은 브라우저에서 http://localhost:8787/health → `"testReady": true`.

**다시 할 필요 없는 것** (처음 한 번만 하는 명령):
- `npm install` — 라이브러리(`node_modules/`) 내려받기. 폴더를 새로 clone했거나 `node_modules`를 지웠을 때만
- `npm run mock:db` — 로컬 DB(SQLite)에 테이블 만들기(`schema.sql`). 이미 만들어져 있음. `.wrangler/state`를 지웠을 때만 다시

## 다시 켜기 — 터널 (탭 ②, 아이폰용)

```
cd ~/Downloads
./cloudflared tunnel --url http://localhost:8787 2>&1 | grep -o 'https://[a-z0-9-]*\.trycloudflare\.com'
```

- `./cloudflared` — 다운로드 폴더에 풀어둔 실행 파일. `./`은 "이 폴더의"라는 뜻
- `tunnel --url http://localhost:8787` — 내 8787 포트를 Cloudflare 서버를 거쳐 공개 https 주소로 연결. 아이폰 스크립트가 https만 받아서 필요
- `2>&1 | grep -o 'https://…trycloudflare.com'` — 로그가 많이 찍히니 주소 한 줄만 걸러서 보여줌. 터널은 그대로 계속 돌아감

**주의: 주소는 켤 때마다 바뀝니다.** 그리고 아이폰 스크립트는 연결할 때의 주소를 기억하고 있어서, 주소가 바뀌면 위젯 새로고침이 실패해요("자동 갱신이 지연"). 그때는 아래 초기화 스크립트로 폰 쪽 연결 기록을 지우고 다시 연결합니다.

### 아이폰 연결 기록 초기화 (터널 주소가 바뀌었을 때)

Scriptable에서 `+` → 새 스크립트 → 아래 붙여넣기 → 이름 `MirinaeReset`로 저장 → 한 번 실행:

```javascript
// 미리내 Scriptable 연결 기록 초기화 (서버 데이터는 그대로, 폰 쪽 세션·캐시만 삭제)
for (const key of ["sseuldon-pilot-session-v1", "sseuldon-pilot-api-url-v1"]) {
  if (Keychain.contains(key)) Keychain.remove(key);
}
const fm = FileManager.local();
for (const name of ["sseuldon-pilot-cache.json", "sseuldon-pilot-budget.json"]) {
  const path = fm.joinPath(fm.documentsDirectory(), name);
  if (fm.fileExists(path)) fm.remove(path);
}
const a = new Alert();
a.title = "초기화 완료";
a.message = "Mirinae를 다시 실행해 일반은행 연결부터 진행하세요.";
a.addAction("확인");
await a.presentAlert();
```

그다음 `Mirinae` 실행 → `일반은행 연결 (팝빌)` → 새 주소 입력 → 같은 값(초대코드 `MIRINAE-MOCK-2026`, 계좌번호 `11012341234` 등)으로 다시 연결. 서버에는 예전 연결이 하나 더 남지만 문제없어요(70일 뒤 자동 만료).

## 자주 겪는 것

- **`Address already in use` / 8787 포트 사용 중** — 예전 서버가 안 죽은 것. `lsof -ti :8787 | xargs kill` (8787 포트를 잡은 프로세스 번호를 찾아 종료) 후 다시 `npm run mock`
- **앱이 "서버가 준비 중"** — `/health`의 `testReady`가 false. 보통 `npm run mock`을 `wrangler.jsonc`(운영 설정)로 잘못 띄운 경우. 반드시 `npm run mock`(= mock 설정)
- **위젯이 갱신 안 됨** — 서버 잔액 캐시 1분. 바로 보려면 앱의 `지금 잔액 새로고침`. 그래도 안 되면 터널 주소가 바뀐 것 → 위 초기화
- **가짜 은행 계좌가 안 보임** — ①을 껐다 켜서 메모리가 비워진 것. 앱에서 `지금 잔액 새로고침`을 한 번 누르면 다시 등록되며 http://localhost:8787/mock/ 에 나타남
- **완전히 처음부터** (서버 연결·세션까지 다 지우기):
  ```
  cd ~/dev/mirinae-local-mvp-v0.7.0/backend
  rm -rf .wrangler/state
  npm run mock:db
  npm run mock
  ```
  `.wrangler/state`가 로컬 DB 파일이 있는 곳. 지우면 빈 DB가 되니 테이블을 다시 만들고(`mock:db`) 켬. 폰 쪽도 위 초기화 스크립트로 맞춰야 함.

```
끄기:   각 탭에서 Ctrl+C
```
